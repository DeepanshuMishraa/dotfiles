# Native Markdown report schema

Create one self-contained Markdown file in this order:

1. **Title and generated timestamp**
2. **Decision** — winner, verdict, weighted score, and the next test
3. **Founder profile** — advantage, taste, constraints, and avoid list
4. **How the machine learned** — round count and love/maybe/no patterns
5. **Finalist leaderboard** — weighted scores and verdict bands
6. **Winning idea** — customer, pain, product, signal, founder connection, wedge, and pricing hypothesis
7. **Evidence for and against** — strongest sources, counterevidence, unknowns, and fatal assumption
8. **Competitors and substitutes**
9. **Seven-day validation plan**
10. **Idea journey** — all rounds and reactions
11. **Evidence ledger** — source titles, dates, states, and links
12. **Limits** — public research cannot prove demand, price, acquisition, or retention

## Rendering rules

- Lead with the decision.
- Keep tables narrow enough to read in Codex.
- Use direct links for source titles.
- Show `Not yet researched` instead of inventing missing fields.
- Preserve rejected ideas in a compact appendix.
- Mark exploratory ideas visibly.
- Do not include HTML, external CSS, JavaScript, or remote assets.

## Final handoff

Return clickable absolute links to:

- the Markdown report;
- the JSON session.

Mention when the report contains hypotheses that still require real customer conversations.
